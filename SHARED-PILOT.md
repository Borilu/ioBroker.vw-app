# Isolated new loopback pilot with shared certificate aliases

Experimental, synthetic CI design. It creates a distinct disabled Admin instance with its own random marker and `auth=true`, `secure=true`, `http2=false`, info logging, and loopback binding before starting it. The new instance refers to the existing synthetic pilot's two certificate aliases and files. The code compares the full certificate-map digest and referenced files before and after operations and **never writes the shared certificate map**. It stops and checks the new instance when the test completes. An existing instance with the target number or a running orphan process blocks creation.

The GitHub job is the only proposed real-controller execution; it uses synthetic data and a disposable network-isolated container. This design is not a production driver. The CI-only driver checks isolation, fixed synthetic instance and paths, the journal lock and markers, and limits writes to creating/configuring/starting/stopping the one test instance. The lock excludes only cooperating tools. Neither ownership checks, a snapshot of the certificate map, nor process/port checks provide database CAS or prevent delayed controller operations. A real maintenance window and further independent validation would be required before applying any adapted procedure to a live host.

Creating an instance can also create its own ioBroker state objects and process, and an Admin implementation may select another port. The procedure compares listener baselines, instance ownership and process/port evidence; unclear outcomes retain the journal and lock for investigation rather than automatically retrying or deleting anything. Shared aliases and certificate files cannot be removed while any instance references them. Authentication evidence covers only the tested anonymous HTTP/socket actions, not all possible endpoints.

The additional `scoped-shared-runner.cjs` takes a separately supplied JSON scope bound to an explicit SHA-256 expected value, and the CI job is prepared to exercise that exact runner against another synthetic controller instance. A potential later private use must independently bind the expected hash to the approved scope, verify paths and ownership, and deploy exactly the reviewed runner and dependencies; a hash calculated from the same untrusted changing file does not establish authorization. The private configuration-generation helper is a different program and is **not** exercised by this CI run. The new end-to-end CI case has not yet run. Neither a matching runner test nor the cooperative lock establishes CAS or excludes concurrent or delayed controller operations.
